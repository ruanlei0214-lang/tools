## Context

netcfg 的默认值现在分散在三处：`NetcfgView.vue` 的 `device` / `form` 初始化字面量、`select()` 里补掩码用的 `'255.255.255.0'`、以及 `netcfg.go` 的 `runtimeConfigPath` 常量。恢复路径更麻烦，除了 Go 常量，Vue 的按钮说明、结果提示和弹窗正文里各写了一遍 `/opt/runtime/pi`——四处必须同时改，漏一处界面就会和实际行为不符。

产物是单个免安装 exe，配置按已定方案编译进去，不在运行时读外部文件。

## Goals / Non-Goals

**Goals:**
- 一份 `config.json` 管住页面默认值和恢复路径，改一处即可。
- 配置写错不至于让程序不可用，且错误对用户可见。
- 随包配置的合法性由测试守住。

**Non-Goals:**
- 不做运行时可改的外部配置文件（已定为编译期嵌入）。
- 不把界面文案做成可配置，不做多语言。
- 不做全局的、供所有模块共用的配置框架——这份配置只服务 netcfg。
- 不持久化用户在界面上填过的值。

## Decisions

**配置文件放在模块目录里，跟着模块走。**
`internal/modules/netcfg/config.json`，用 `//go:embed config.json` 嵌入同包的 `config.go`。放在模块内而不是仓库根目录，是为了守住模块独立约束：netcfg 被 profile 剔掉时，它的配置也一起消失，不会在别处留下一段无人认领的配置。也因此没有做成全局配置——目前只有一个模块有这个需求，做成共享框架属于超出需求的抽象。

**前端不再持有任何默认值字面量，一律向后端要。**
新增 `Service.Defaults() Settings`，前端在 `onMounted` 里取一次填表单。备选方案是把默认值也塞进 `module.ts` 的清单里，但那份清单是给外壳做导航用的，塞业务默认值会让它和后端各存一份，又回到"改两处"的老问题。

**配置不可用时返回兜底值 + 一段说明，而不是返回 error。**
`Defaults()` 不返回 error，而是在 `Settings.Warning` 里带回原因。走 error 通道的话前端只能弹一条错误横幅，然后表单是空的、页面基本不能用；而配置坏了并不影响 SSH 那套功能，没有理由连带废掉。`Warning` 非空时前端单独渲染一条常驻提示，不与操作结果的横幅抢同一个位置——否则用户点一次"测试连接"就把配置告警冲掉了。

**校验只挡住会造成实际危害的两项：端口范围和恢复路径必须是绝对路径。**
恢复路径是要拼进 `rm -f` 的，空字符串或相对路径都可能删到意料之外的东西，必须挡。端口越界会让 `dial` 报一句难懂的错，早挡早清楚。其余字段（地址、用户名、密码、掩码、网关）不在加载时校验：它们本来就是给用户改的初始值，下发前 `validate()` 已经会拦，加载时再拦一遍等于逼着现场必须先填对配置才能打开页面。

**恢复路径在界面上的兜底文案用"网络配置文件"，不重复写死路径。**
`Defaults()` 是异步的，首帧渲染时路径还没到。前端用 `配置的路径 || '网络配置文件'` 渲染，既避免首帧出现"删除设备上的 ，让…"这种断句，也不用在前端再抄一份 `/opt/runtime/pi`——抄了就又多一处要同步的地方。

**连接卡片只留「设备地址」一个输入框。**
端口、用户名、密码在现场基本不变，既然已经进了配置，界面上再摆三个输入框只是噪音。它们仍然通过 `device` 传给后端，只是不渲染。代价是现场换账号必须重新构建——判断依据是这三项的变动频率远低于设备地址；而且 `dial` 失败时的错误消息里带着 `host:port`，排查时还看得到实际用的端口。

**输入框的 placeholder 保持写死，不进配置。**
它们是"该填成什么样"的例子，不是默认值——默认值现在会真的填进输入框，placeholder 只在输入框空着时出现。把示例文本也搬进配置，等于让现场为了改一个默认地址去维护两个字段。

**随包配置的合法性交给单测。**
`go:embed` 只保证文件存在，不看内容，配置写坏要到运行时才由兜底接住——那时用户看到的是"配置不可用"，问题已经进了产物。`config_test.go` 直接解析嵌入的那份配置并断言通过校验，把这个错误挪到 `go test` 阶段。

## Risks / Trade-offs

- **改配置必须重新构建，现场改不了** → 这是选定方案的固有代价。文档里写明这一点，并把 `go run ./tools/pickbuild` / `build.ps1` 作为改完之后的标准动作。
- **密码明文进 exe** → 配置里的 `password` 会以明文留在产物里，`strings` 一翻就能看到。默认留空，文档里写明这条，不建议在配置里放生产密码。
- **兜底可能掩盖配置错误** → 兜底只是运行时的最后一道，配置错误的主要防线是 `config_test.go`；同时 `Warning` 会显示在界面上，不静默。
- **默认值改成异步获取后，首帧表单是空的** → 只影响一帧，且输入框本来就有 placeholder；不引入 Suspense 之类的机制来消除这一帧。
- **端口、用户名、密码从界面上撤掉后，现场改不了这三项** → 属于有意取舍，见上面的决策；文档里写明要改就得改配置再重新构建。
