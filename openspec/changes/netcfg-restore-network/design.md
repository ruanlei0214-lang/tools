## Context

netcfg 模块已经具备完整的 SSH 短连接骨架：`dial` 建连、`run` 执行命令、`quote` 包裹 shell 参数。本次要加的动作只有"删一个文件"，正好落在这套骨架上，不需要引入新结构。

前端 `NetcfgView.vue` 已有 `call()` 统一处理 busy 状态与错误 banner，以及"下发配置"用的两段式确认（`confirming` 标志切换按钮组）。新交互沿用同一套模式即可。

## Goals / Non-Goals

**Goals:**
- 一个按钮完成"删除 `/opt/runtime/pi`"，成功后弹窗提示需要重启机器人控制器。
- 改动局限在 netcfg 模块的两个文件加一份重新生成的绑定。

**Non-Goals:**
- 不由工具执行重启，也不提供重启入口。
- 不做删除前的文件备份或还原。
- 不做重启后的自动重连与探活轮询。
- 不抽象通用的"远程文件操作"能力给其他模块用。

## Decisions

**删除是唯一的远程动作，重启不由工具代做。**
后端只加 `RestoreNetwork(d Device) error` 一个方法，执行 `rm -f /opt/runtime/pi` 之后就结束。重启机器人控制器的影响面比删一个文件大得多，什么时候能重启只有现场清楚，工具替用户按下去不合适。所以模块里不留 `RebootDevice` 这类方法——不留这个口子，后续就不会有人顺手调它。一次调用一条短连接，与模块现有约定一致。

**删除用 `rm -f`。**
`-f` 让文件不存在时退出码仍为 0，直接满足"文件本来就不存在也算成功"的要求，不必额外判断 stderr。路径是固定字面量，用 `quote` 包一层保持与 `ApplyConfig` 一致的写法习惯。

**重启提示用模块内自带的模态弹窗，且只有一个按钮。**
需求明确要"弹窗"，行内确认（下发配置那种切换按钮组的做法）达不到这个效果。弹窗里没有要用户做的决定，所以只放一个"知道了"——它的作用是别让人删完就忘了还要重启。同一句话也写进 banner，弹窗关掉后仍能看到。项目没有 UI 组件库，所以在 `NetcfgView.vue` 里写一个 scoped 的遮罩 + 卡片，约二十行 CSS，不进全局 `style.css`，避免变成跨模块的共享控件。不用 `window.confirm`：WebView2 里它的外观与应用风格脱节，且会阻塞渲染。

**删除动作本身不加二次确认。**
按钮叫"一键恢复网络"，中间再插一次确认就不是一键了。改用文案兜底：按钮旁的 hint 写明会删除哪个文件，弹窗里也复述一遍已删除的路径。

## Risks / Trade-offs

- **删掉 `/opt/runtime/pi` 后控制器行为由设备自身启动脚本决定，工具无法保证网络一定恢复** → 按钮文案与提示只承诺"已删除配置文件"，不宣称结果。
- **误触会直接删设备上的文件** → 为保住"一键"体验不加二次确认，改由按钮旁的 hint 与弹窗文案写明删除的具体路径，让后果可见。
- **用户可能删完就走，忘了重启，以为功能没生效** → 用模态弹窗而不是一条 banner 来提示重启，强制它进入视线；提示文案同时留在 banner 里备查。
