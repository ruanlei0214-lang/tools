## Context

网络配置页刚换成三步竖排布局，操作结果已经用固定高度的 `.status-slot` 占位。同页还有配置告警走 `v-if` 的 `.banner`，以及全局里给旧表格准备的行样式。本变更只清这些，不重做布局。

约束：少改、不抽象、不跨模块共享控件。

## Goals / Non-Goals

**Goals:**
- 去掉排版后已经没有引用方的样式与过时注释。
- 配置告警与操作结果共用同一条固定高度状态槽，整页不再因「有没有字」上下跳。
- 状态槽的行为写进 spec，避免下次又拆成两套。

**Non-Goals:**
- 不抽 App / netcfg 共用的 modal 组件（模块独立优先）。
- 不把 `NetcfgView` 的 scoped CSS 拆成独立文件。
- 不改后端、绑定、网口映射。
- 不解决「第 2 步在无网口时整块消失」造成的跳动——那是内容区显隐，不是状态槽。

## Decisions

### 配置告警与操作结果共用一条状态槽

备选 A：告警另开一条固定高度的空槽（永远两行占位）。  
备选 B：告警与结果共用 `.status-slot`。

选 B。告警只在配置坏了时出现，和操作结果几乎不同时需要；开两条槽等于永远多一行空白。共用时规则：

- `configWarning` 非空 → 状态槽显示告警（`err`），**操作开始时不清掉它**（`call()` 只清 `banner`）。
- `configWarning` 空且 `banner` 有值 → 显示操作结果。
- 两者都空 → `idle` 占位（虚线浅底、无字）。

展示用一个 computed（例如 `status`）拼出 `{ kind, text } | null`，模板只绑这一处，避免两套 DOM。

### 删全局 `readonly` / `blank`，不删整张表样式

hello 和其他未来模块可能还用 `<table>` + `.selected`。只删确认零引用的 `tbody tr.readonly` 与 `tbody tr.blank`（含 hover）。`.selected` 和基础 `th/td` 留下。

### 不把 CSS 外提

620 行里大半是本页排版。外提成 `.css` 要改构建约定、换作用域，收益只是「文件变短」，不符合「尽量少改」。

## Risks / Trade-offs

- [告警与结果同槽，用户可能以为告警被操作冲掉] → `call()` 只清 `banner`；有 `configWarning` 时 computed 始终优先告警，操作成功文案被压住直到配置修好。这是刻意的：配置坏了改地址也不可信，告警必须压在上面。
- [idle 虚线框有人觉得丑] → 比「空白塌陷导致跳动」代价小；若以后要更隐形，可改成同色底无边，高度规则不变。
- [长文案在 40px 里被裁] → 已有 `overflow: auto`；本变更不调高度，避免又把下面顶走。

## Migration Plan

纯前端样式与展示逻辑，无数据迁移。改完 `wails build` 或 `npm run build` 验证；目测：无消息时状态槽仍在、点测试连接下方网口区纵坐标不变、配置告警出现时占同一槽。
