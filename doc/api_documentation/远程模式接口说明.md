API接口说明

通信方式

使用TCP/IP协议，机器人控制器作为服务端，端口号为9001。控制器默认IP地址为192.168.1.136，若重新配置过IP，则使用配置后的IP进行连接。

为方便数据解析，API接口统一采用Json字符串进行数据通信，仅支持UTF8编码。

API接口说明

请求数据结构如下：

{

    "id": 1, // 请求ID，用于标识请求，用户自定义，可以为数据或字符串，返回请求时原值返回

    "ty": "type/action", // 请求类型，由相应接口定义

    "db": {} // 请求数据，具体内容由相应接口定义

}

返回数据结构如下：

{

    "id": 1, // 请求ID，与请求参数一致

    "ty": "type/action", // 请求类型，与请求参数一致

    "db": {}, // 返回数据，具体内容由相应接口定义

    "err": "code/msg" // 如果请求失败，会有该字段，code是错误码，msg是具体的错误消息

}

接口没有数据返回时，默认返回数据如下，接口不再进行返回数据说明。

{

    "id": 1, // 请求ID，与请求参数一致

    "ty": "type/action", // 请求类型，与请求参数一致

}

工程相关接口说明

运行脚本

客户端直接发送脚本运行

请求数据如下：

{

	"id": "mdo8zdy30wscc06e", // 客户端生成，请求返回时会返回该字段

    "ty": "project/runScript", // 请求类型，固定值

    "db": {

        "scripts": { // 脚本集合

            "main": "print(1)\nrunScript(\"t1\")\nprint(2)\nenterRemoteScriptMode()", // 主程序

            "subThreads": { // 可选参数，子线程，可通过runScript调用

                "t1": "print(3)\ncallSubprogram(\"p1\")" // key为线程名，value为线程程序代码

            },

            "subPrograms": { // 可选参数，子程序，可通过callSubprogram调用

                "p1": "print(4)" // key为程序名，value为子程序代码

            },

            "interrupts": { // 可选参数，中断程序，可通过设置中断条件触发调用

                "in1": "print(5)" // key为中断名，value为中断程序代码

            }

        },

        "vars": { // 可选参数，脚本共用变量，多脚本共享，同工程变量

            "v1": 1, // key为变量名，value为变量值

            "v2": "hello"

        }

}

}

运行工程（内部接口）

请求数据如下：

{

    "id": "m8y21rn20ws8a974", // 请求id，前端生成

    "ty": "project/run",

    "db": {

        "id": "m8wope1d0pr0d443" // 工程id

    }

需要注意的是，如果脚本设置了断点，当运行到断点处时，工程自动进入暂停状态。

通过工程映射索引号运行工程

请求数据如下：

{

    "id": "message",

    "ty": "project/runByIndex",

    "db": 1 // 对应IO配置界面中工程映射的索引，需先绑定工程

}

单步运行（内部接口）

运行一行脚本，当没有工程在运行时，需传入工程id，当工程暂停时，再次调该接口不需要传工程id，工程执行一行代码后再次暂停。

请求数据如下：

{

    "id": "m8y21rn20ws8a974", // 请求id，前端生成

    "ty": "project/runStep",

    "db": {

        "id": "m8wope1d0pr0d443", // 工程id,刚开始运行时必传，后续运行时可不传

    }

}

注：单步运行时，只有主任务会根据该接口，一行一行的运行（调用一次运行一行），线程和中断会正常执行，所以工程会处于运行状态。

全局变量相关接口说明

全局变量定义

全局变量默认是掉电保存的，且运行时的值也会保留。即全局变量的值可由用户修改或运行时被修改，并且工程结束后值不会恢复到运行前，会保留当前值。

全局变量和工程变量的值以json字符串的形式保存。

下面是不同类型数据的示例，所有符号都必须是英文符号，不建议使用中文，避免：

1.	数字，直接输入数字即可：100 或2.1

2.	字符串，必须使用双引号：”abcas”

3.	数组，使用中括号,：[2,4.1,”abc”]，[[1,2,3],[4,5,6]]

4.	Map：{“jp”:[1,2,3,5,6,8]}，{“a”:{“b”: 1}}

给地址段设置数据类型

只对保持和输入寄存器有效，对应功能码0x03,0x04,0x06,0x10。

默认数据类型是U16。

请求数据如下：

{

    "id": "m912rb1b0wsc2742",

    "ty": "ModbusTcp/setType",

    "db": {

        "name": "deviceefx", // 设备名

        "tableName": "tablel3r", // 表名

        "type": "I32", // 数据类型：I16,I32,I64,U16,U32,U64,F32,F64

        "addr": 0, // 起始地址，一个地址对应两个字节长度，即16位

        "count": 2 // 地址数量，该数量应与对应的数据类型长度一致，可连续设置多组，例如将4个地址设置为两个U32类型数据

    }

}

注意：0x06功能码只有一个地址，所以只能设置为I16或U16。

远程脚本模式接口说明

进入方式

通过2.2.1.1运行脚本时，在主任务脚本中调用enterRemoteScriptMode()指令

调用2.2.1.2接口

通信方式

使用TCP/IP协议，机器人控制器作为服务端，端口号为9002。控制器默认IP地址为192.168.1.136，若重新配置过IP，则使用配置后的IP进行连接。

为方便数据解析，API接口统一采用Json字符串进行数据通信，仅支持UTF8编码。

接口说明

{

    // 控制命令，当存在此字段时，其他字段无效

    // 可选值：resume: 恢复运行,stop：停止运行, interrupt：中断当前指令

    "command": "resume",

    "script": "print(6)", // 要执行的脚本代码

    "vars": ["P1", "v1"], // 可选参数，执行完脚本后，将这些变量的值返回，如果工程被stop停止，则不返回

    "...": "..." // 自定义参数，例如"id": "mdo8zdy30wscc06e"

}

返回值说明：

{

    "code": 0, // 0表示成功，其他表示失败

    "msg": "OK", // 错误信息

    "vars": {

        "P1": 1, // 脚本执行后，返回的变量值

        "v2": "hello"

    },

"...": "..." // 自定义参数会原值返回

}

运行机制

通过上面的接口发送的脚本会被加入到运行队列中，按顺序执行，队列长度64，队列满了之后会返回错误。

每个请求中，脚本内定义的local类型的变量只在当前的指令脚本中生效。其他变量将持续生效。

可用指令与正常编写脚本相同。

如果执行类似while(true)这种不会退出的脚本，可通过发送interrupt请求打断运行。

因为远程脚本模式是在工程运行状态下执行的，可通过2.2.1中的相关工程运行控制指令来暂停、恢复或停止工程。
